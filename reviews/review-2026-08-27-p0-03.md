## 一、需要处理的问题（按重要性排序）

### 1. 死代码：Colors.xaml 中约一半令牌从未被引用

grep 全仓验证，以下键 **0 引用**：

| 键 | 位置 | 状态 |
|---|---|---|
| `AccentColor` / `AccentHoverColor` / `AccentPressedColor` | Colors.xaml:11-13 | 死 |
| `AccentBrush` / `AccentHoverBrush` / `AccentPressedBrush` | Colors.xaml:28-30 | 死（仅被死键引用） |
| `FocusColor` / `FocusBrush` | Colors.xaml:18,35 | 死 |
| `DisabledColor` / `DisabledBrush` | Colors.xaml:19,36 | 死（禁用反馈用的是 Opacity=0.55，Controls.xaml:62） |

另外 `Typography.xaml:3-9` 的 `TextBlockBaseStyle` 也是死的：定义了 2 个 Setter，
但其余 11 个 TextBlock 样式全部手动重复 `FontFamily` + `SnapsToDevicePixels`，
无一处 `BasedOn` 引用。要么删除，要么让其样式 `BasedOn` 收编（后者是 Design System
的正确做法，可减约 20 行重复）。

### 2. 架构缺口：Design System 只被 Windows 项目物理承载，Widget 复用未决策

P0-03 brief In Scope 声称"为 TODAY、ANIME 和后续 Widget Mock 提供同一套视觉基础"；
ARCHITECTURE.md 声称"Main App 与未来 Widget 使用同一套令牌命名"。但资源字典物理位于
`ReminNote.Windows/Resources/DesignSystem/`。P0-06 创建 `ReminNote.Widget` 项目时：

- 引用 ReminNote.Windows → 错误依赖方向（整个主 UI 程序集被拖入）；
- 复制字典 → 违反"共享一个 design system"（主计划 #49）；
- 抽共享资源项目/包 → 需要新架构决策（当前 ADR 无记录）。

建议立即在 DECISIONS.md 记录该前置决策（ADR-0008），而不是等 P0-06 当天拍脑袋。

### 3. MainWindowViewModel.ActiveTitle 的通知与赋值源分离（脆弱，当前正确）

`MainWindowViewModel.cs:59` 在 `Navigate()` 内手动 `OnPropertyChanged(nameof(ActiveTitle))`。
正确性依赖"`CurrentPage` 只有一个写点"的隐性约定。将来任何新路径（恢复页面、快捷键）
直接赋 `CurrentPage` 将导致标题与页面不同步且无异常提示。建议改用
`[ObservableProperty]` + `[NotifyPropertyChangedFor(nameof(ActiveTitle))]`。

### 4. "今天/动画"标题三处硬编码重复

- `MainWindowViewModel.cs:22-23`（NavigationItems 构造）
- `MainWindowViewModel.cs:41-42`（ActiveTitle switch 再次硬编码）
- `TodayResources.xaml:7`、`AnimeResources.xaml:7`（占位页标题）

P0-04/05 高保真 Mock 会把页面标题数据化，因此本清单只在共享壳内消除本文件重复
（ActiveTitle 从 NavigationItems 查询），不改 Features 目录。

### 5. 文档与实现不一致 / 笔误

- **DEVELOPMENT.md:24**："脚本会优先使用 PATH 中可用的 .NET SDK，若当前进程 PATH 尚未刷新，
  则回退到标准 x64 安装路径" —— 与 `resolve-dotnet.ps1` 实际流程**顺序相反**
  （先探测 `%ProgramFiles%\dotnet\dotnet.exe`，找到含 10.x SDK 即返回，才轮询 PATH）。
  实机验证：PATH 首个 dotnet 为 `C:\Program Files (x86)\dotnet`（无 SDK），裸 `dotnet build`
  失败；仓库脚本因"先 x64 后 PATH"而正常。文档必须改正，否则会误导后续排障。
- **TESTING.md:78**："D:Anime.devdata" → 应为 `D:\Anime\.devdata`。
- **TESTING.md:45**："仓库根目录为 D:Anime。" → 格式统一为 `D:\Anime`。

### 6. 环境问题（非代码，需人工处理）

PATH 中 `C:\Program Files (x86)\dotnet\dotnet.exe` 位于 `C:\Program Files\dotnet\dotnet.exe`
之前，且 x86 版本无任何 SDK，导致一切裸 `dotnet` 命令失败。建议调整 PATH 顺序或删除 x86 条目。
`global.json` 锁 10.0.100 + rollForward latestFeature 与已安装 10.0.300/400 兼容，无需改动。

### 7. 过时注释

`ReminNote.Windows/AssemblyMarker.cs` 注释"before the App Shell is introduced in P0-02"
已过时（壳在 P0-02 引入，当前处于 P0-03）。Core/Infrastructure 的 Marker 注释仍成立。

## 任务 T3：MainWindowViewModel 通知机制与字符串重复

文件：src/windows/ReminNote.Windows/ViewModels/MainWindowViewModel.cs

问题 1（必须修）：ActiveTitle 是 CurrentPage 的派生值，当前在 Navigate() 末尾手动
OnPropertyChanged(nameof(ActiveTitle))。若未来其它路径修改 CurrentPage，标题将不同步。

做法（二选一，优先 A）：
A) 使用 CommunityToolkit.Mvvm 部分属性特性（net10.0-windows + MVVM Toolkit 8.4.2 支持）：
   - MainWindowViewModel 改为 public sealed partial class；
   - CurrentPage 改为：
       [ObservableProperty]
       [NotifyPropertyChangedFor(nameof(ActiveTitle))]
       public partial ShellPageViewModel CurrentPage { get; private set; }
   - 构造函数中直接赋初值 todayPage；
   - 删除 Navigate() 内手动 OnPropertyChanged(nameof(ActiveTitle))；
   - 保留 _todayPage/_animePage 私有字段。
B) 若 A 引发编译问题：回退为字段形式，在 CurrentPage setter 内（SetProperty 之后）
   OnPropertyChanged(nameof(ActiveTitle))，删除 Navigate() 中的手动通知。

问题 2（建议修）：消除本文件内"今天/动画"硬编码重复（不改 Features 目录）：
   ActiveTitle 保留类型 switch（TodayPageViewModel=>Today、AnimePageViewModel=>Anime），
   但标题改为从此处查询：NavigationItems.First(i => i.Page == ShellPage.Today).Title
   （Anime 同理），兜底 "ReminNote"。
   要求：首次启动（默认 Today）时 ActiveTitle 正确显示"今天"。

禁止事项：
- 不改 NavigationItemViewModel.cs 的 record 结构（除非必要且最小）。
- 不改 TodayPageViewModel / AnimePageViewModel（并行窗口所有）。
- 不引入新依赖。
