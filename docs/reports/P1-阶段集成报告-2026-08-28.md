## P1 做了什么

P1 把 P0 的界面 Mock 之后真正需要的 Task 基础能力落到了可验证的本地业务链路中：

1. 在 Core 中建立真实 Task 领域模型：UUID v7、ANYTIME/TIME/RANGE 时间形状、本地日期/时间语义、跨午夜 RANGE、结果记录和确定性校验；结果记录后的计划改期会被安全拒绝，失败不会留下部分状态变更。
2. 在 Infrastructure 中建立 SQLite + EF Core 持久化：固定开发库 `.devdata/reminnote.sqlite`，真实 migration、Task 映射、关系型 CHECK 约束和 repository；当前只创建 `tasks` 与 EF 自身系统表，不提前创建 Reminder/Anime/Sync 表。
3. 在 Application 层建立 Task CRUD、查询和结果记录边界，使写入经过 application service，查询返回 Core snapshot，Core 不依赖 WPF、EF Core、Windows API 或日志框架。
4. 建立 75 项自动化测试，覆盖领域不变量、UUID v7、时间值对象、跨午夜、结果合法性、回滚不变性、SQLite migration/CRUD/约束和 application/query 边界。
5. 建立 `ReminNote.P1ManualHarness`，供开发库人工验证 schema、Create/Read、Update、Result、Delete、重启保留、非法输入、失败恢复和数据安全边界。
6. 保留并修复 P0 Mock 的用户可见行为：主程序单实例与干净退出、Main/Widget 实例隔离、Quick Add 连续添加反馈、Anime 详情浮层、Widget 滚动/缩放/面板互斥；这些修复不把 P0 Mock 冒充为真实 Task UI。

P1 明确没有提前实现真实 Reminder 调度、ReminderRule/Instance、Anime 网络/Bangumi、同步/下载/播放、Agent IPC/Single Writer，也没有把 P0 Quick Add 接到真实 SQLite Task 写入。
