# ReminNote P1 阶段预报告

- 报告日期：2026-08-28
- 前置基线：P0 `codex/p0-integration@867af2b`
- 性质：开发前设计与并行拆分预报告，不是开始 P1 编码的授权
- 权威依据：`ReminNote_MASTER_DEVELOPMENT_PLAN.md` 第 P1、Git workflow、Commit policy 章节，以及 `ARCHITECTURE.md`、`PRODUCT_RULES.md`、`DECISIONS.md`、`docs/PARALLEL_DEVELOPMENT.md`

## P1 目标与范围

P1 的目标是把 P0 的进程内 Task Mock 替换为可长期维护的真实 Task core 和本地 SQLite 持久化。主计划要求纳入：

- UUID v7 Task ID；
- `TaskTimeType` 与 `TimeSpec`；
- `ANYTIME`、`TIME`、`RANGE`；
- 本地日期/时间语义和跨午夜范围规则；
- 当前 Slice 所需的真实结果模型；
- SQLite、EF Core、真实 migration 和 schema constraints；
- repository/query/application service 的基本 CRUD 路径；
- Noda Time abstraction；
- 确定性领域校验；
- 时间形状不变量的单元测试。

## 明确不做

P1 不提前实现：

- ReminderRule、ReminderSchedule、ReminderInstance 或真实提醒调度；
- Toast、Tray、Widget Alert 生产化；
- Agent IPC、Named Pipe、Single Writer 迁移（属于 P2.5）；
- Anime 网络、Bangumi、同步、下载和播放；
- Android、插件平台、Updater；
- 为未来 Reminder/Anime/Sync 预建空表；
- 一次性平表原型 schema；
- 运行时语言切换和与 P1 无关的全局 UI 改造。

## 架构约束

1. `ReminNote.Core` 只放领域类型、值对象、校验和应用边界抽象；不得引用 WPF、Windows API、EF Core 或 Serilog。
2. `ReminNote.Infrastructure` 承担 SQLite/EF Core DbContext、实体映射、migration、repository 和持久化实现。
3. `ReminNote.Windows` 在 P1 只接入必要的 application/query 边界；TODAY/Widget 的真实任务体验主要属于 P2，不能在 P1 偷渡大规模 UI 功能。
4. P1 使用真实 migration，从第一天按长期模型设计 schema；开发数据库可以重置，但必须继续位于 `.devdata/`，不可触碰生产路径。
5. P2.5 开始后 Agent 才成为唯一业务写入者；P1 不得设计出无法迁移到该边界的业务写入 API。
6. 所有新增依赖必须先说明用途、许可证、维护性和安全影响；中央包版本、lock 文件、Solution 登记由集成窗口统一串行修改。

## 建议的窗口与 worktree 拆分

所有 P1 窗口使用独立 worktree，分支统一采用 `codex/p1-*`。下表中的“可并行”以依赖冻结为前提：

| 编号 | 工作窗口 | 主要所有权 | 前置条件 | 可否并行 |
|---|---|---|---|---|
| P1-00 | 集成/决策窗口 | P1 brief、ADR、公共依赖版本、Solution、最终合并 | P0 正式人工验收、用户批准 P1 | 串行起点 |
| P1-01 | Task Core 窗口 | `src/windows/ReminNote.Core/**` 中 Task domain、TimeSpec、校验和接口草案 | P1-00 的边界冻结 | 可与 P1-05 文档草案并行 |
| P1-02 | Persistence 窗口 | `src/windows/ReminNote.Infrastructure/**` 的 SQLite/EF Core、映射、migration、repository 实现 | P1-01 domain contract 冻结 | 可与 P1-03 测试窗口并行；schema 变更需串行 |
| P1-03 | Tests 窗口 | 新增测试项目及时间形状/值对象/持久化测试 | P1-01 类型可引用；包和 Solution 登记由集成窗口处理 | 可与 P1-02 并行 |
| P1-04 | Application boundary 窗口 | Core application/query/command 抽象与 Infrastructure 实现适配 | P1-01 + P1-02 接口稳定 | 不与 schema/migration 同时改同一契约 |
| P1-05 | 文档与验收窗口 | `docs/slices/P1-*`、手测说明、数据迁移说明草案 | P1 范围冻结 | 可与 P1-01/P1-02/P1-03 并行，但最终文档串行校对 |
| P1-06 | 集成与人工验收窗口 | Solution、Directory 包管理、lock 文件、DI 接线、P1 全量测试和用户验收 | P1-01 至 P1-05 交付 | 必须串行 |

P1-02 与 P1-03 可以同时推进，但测试窗口只能针对已经冻结的 domain/schema 契约写测试；一旦修改公共契约，必须暂停相关窗口并重新形成版本化决策。

## 可以并行的工作

在 P1-01 的领域契约冻结后，可以并行：

- 持久化实现与测试项目编写；
- domain 不变量单元测试与 SQLite migration 测试夹具；
- P1 Slice 文档、手动验收表和数据安全说明；
- 不改公共配置的测试数据 fixture、临时数据库生命周期和故障场景设计；
- 只读的 CI 诊断和测试覆盖规划。

每个并行窗口必须只写自己的 worktree 所有权范围；发现需要改中央包、Solution、根级脚本或公共资源时，写集成请求，不直接越界。

## 不可以并行的工作

以下事项必须由集成窗口或单一指定窗口串行完成：

- `TaskTimeType`、`TimeSpec`、跨午夜和本地日期所有权等公共领域契约的改动；
- 同一张表/同一组 migration 的生成、重命名、删除和回滚策略；
- EF Core 版本、Noda Time 版本、中央包管理和 lock 文件更新；
- `ReminNote.sln`、`Directory.Build.props`、`Directory.Packages.props`、`global.json`、根级脚本和 CI；
- Core/Infrastructure/Windows 的项目引用边界调整；
- DI 组合、真实数据库路径接入和任何 Main App 写入路径；
- P1 分支合并、全量 restore/build/test、migration 从空库到当前库的验收；
- P1 人工验收及是否进入 P2 的最终判断。

这些事项如果同时修改，会产生不可安全合并的 schema、依赖或写入路径分歧；不能通过事后简单解决冲突代替决策。

## P1 验收门槛

- 空数据库可以通过真实 migration 建立目标 schema；升级路径可重复，禁止依赖删除数据库作为正常升级方式。
- 合法/非法 `ANYTIME`、`TIME`、`RANGE` 组合、跨午夜检测、本地日期归属和值对象相等性有真实自动化测试。
- CRUD/query/application service 通过临时开发数据库验证；失败不会写入生产路径。
- `ReminNote.Core` 依赖边界仍通过；P1 不创建 Reminder/Anime/Sync 空表。
- locked restore、Release build、测试项目和现有 P0-07 门禁全部通过。
- P1 手动验收说明包含启动命令、数据库路径、创建/读取/更新/删除、重启后数据保留、非法输入和失败判定。
- 用户完成重要用户行为验收后，才可合并到 `main` 或进入 P2。

## 提交与审查规则

- 每个窗口只提交有意义的逻辑单元，例如 domain、storage、tests、application boundary；不使用 `WIP`、`try fix` 等无信息提交名。
- 按仓库治理约定使用 `git commit -s` 写入 `Signed-off-by`。
- 开发窗口只做本地提交，不自行 push、merge、rebase、tag 或 release；集成窗口在用户明确授权后串行处理。
- 所有 schema、migration、写入路径和安全边界变更必须在 PR/报告中说明影响与回滚方式。

## 开始 P1 前需要确认的细节

进入 P1-00 时再由用户确认：SQLite 开发文件的具体相对路径、是否允许开发期间重置 `.devdata`，以及需要保留的现有 P0 Mock 展示行为。GitHub 仓库已按当前交付要求创建为 Private；未来是否改为 Public 仍需单独确认。Noda Time 和 UUID v7 的具体实现版本应由集成窗口根据当前 .NET 10 SDK 和包锁定策略确认后记录 ADR。
