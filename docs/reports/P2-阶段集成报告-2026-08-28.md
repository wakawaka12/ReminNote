## 四、实际已实现能力

### Task / Today

- Core 维持三种时间形状和本地 civil date/time；跨午夜不增加冗余布尔值，归属开始日期。
- Today 使用调用方 `Instant` 经 `IUserTimeZoneProvider` 转为本地时间；工作日边界来自 `app_settings`，早于边界时回到前一自然日。
- 默认分组为 `OVERDUE`、`MORNING`、`AFTERNOON`、`EVENING`、`ANYTIME`、`COMPLETED`；未来计划不进入 Today，已完成历史计划不进入活动 Today。
- `TIME` 超过计划时刻才进入 `OVERDUE`；结束 RANGE 无结果为 `AWAITING RESULT` 并计入 `NEEDS REVIEW`，不会自动记录 `MISSED`。
- `DONE` 通过 `RecordResultAsync` 记录 `COMPLETED`；`PARTIAL` 只允许 RANGE；`RecordedAt` 只表示记录动作时间。
- Quick Add 经过确定性 Parser；当前 P2 支持日期/时间/RANGE，不实现标签和优先级字段，遇到保留语法直接拒绝。

### 历史、改期、继续和写入

- 当前结果状态是 Task 上的覆盖式 snapshot，但每次结果记录追加不可变 `task_history` 事件；P1 已有结果 Task 的 P2 migration 会回填 `ImportedResult` 快照。
- 计划改期记录 `PlanChanged` 旧计划快照；已有结果 Task 继续拒绝改期。排序只在同日期同 Today 分组内交换 `sort_order`；继续只允许 `PARTIAL RANGE`，生成新的 UUID v7 Task 和 `continued_from_task_id`。
- P2 的 Task/历史写入通过应用服务、显式事务和 `Local\ReminNote.P2.TaskWrite` 命名 Semaphore 保护；失败/超时不应静默覆盖或留下半写。
- `TaskWorkspace.Initialize()` 成功前拒绝普通读写；Main 和 Widget 通过仓库根目录校验后固定使用 `<repo-root>/.devdata/reminnote.sqlite`。

### Main / Widget 组合

- Main `App.xaml.cs` 在窗口显示前注册并初始化真实 `TaskWorkspace`，TODAY ViewModel 获取真实 Today/application/query/clock。
- Widget 正式入口必须提供 `--repo-root`，初始化同一个 `TaskWorkspace`，通过 2 秒 `DispatcherTimer` 轮询 Today；写入后主动刷新。
- Main 与 Widget 的单实例激活使用各自的本地命名管道，但该管道只做宿主激活，不承载 P2 Task 业务命令。
