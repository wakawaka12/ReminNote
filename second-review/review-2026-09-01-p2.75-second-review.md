## 4. 关键契约核对

### 4.1 已有的正向实现证据

- P2.75-01 的 `eff1729:src/windows/ReminNote.Infrastructure/Persistence/Backup/SafetyBackupService.cs:448-524` 使用独立 SQLite backup 目标，而不是简单复制 live DB；目标设置了 `journal_mode=DELETE` 和 `synchronous=FULL`，随后关闭连接、刷新并校验 artifact。`eff1729:.../SafetyBackupService.cs:554-617` 对最终 artifact 做 SQLite header、integrity、foreign key、长度和 hash 校验。
- P2.75-01 对路径 canonicalization、profile containment、reparse point、同名 RunId 目标和目标存在性有检查，见 `eff1729:.../SafetyBackupService.cs:181-277`、`:325-428`、`:1034-1190`。manifest 采用受限大小、CreateNew/WriteThrough、flush 后 atomic move，见 `eff1729:.../SafetyBackupService.cs:619-685`。
- P2.75-02 的 runner 有 bounded lock/quiescence、源 fingerprint 重读、Candidate staging、明确的 forward migration id、Candidate verify 和 startup gate，见 `bb3d167:src/windows/ReminNote.Infrastructure/Persistence/P275/P275MigrationRunner.cs:64-145`、`:255-400`、`:402-506`；EF applier 只对 Candidate 调用指定 migration，见 `bb3d167:.../P275EfForwardMigrationApplier.cs:13-82`。
- P2.75-03 的 CandidateVerifier 在只读/query-only 连接和事务中检查 SQLite integrity、FK、schema、history、关键表行数/hash，并在末尾复核 fingerprint，见 `3ba6548:src/windows/ReminNote.Infrastructure/Persistence/P275/P275CandidateVerifier.cs:274-459`、`:513-544`、`:614-732`。marker 写入使用 bounded 序列化、临时文件、WriteThrough/Flush 和 atomic replace，见 `3ba6548:.../P275MigrationStateStore.cs:49-150`。
- P2.75-02 的锁使用 `FileShare.None` 并有 bounded retry，见 `bb3d167:.../P275MigrationLock.cs:13-95`；P2.75-02 的失败分支保留 Candidate 并记录失败状态，见 `bb3d167:.../P275MigrationRunner.cs:800-894`。这些是局部静态优点，不等于集成后的成功证据。

### 4.2 关键断点

契约要求的是一条完整且可恢复的链路，但当前代码实际分成三套兄弟实现：02 的 runner 接受 02 自己的 `IP275CandidateVerifier`/state port（`bb3d167:src/windows/ReminNote.Infrastructure/Persistence/P275/P275MigrationContracts.cs:673-692`），03 的 verifier、marker、status 和 recovery 使用 03 自己的公共类型；同一路径的 contracts 文件在 merge-tree 中直接冲突。01 的 `SafetyBackupService` 没有在可见实现中接入 runner。因而 Backup、Verify、marker 和 recovery actor 尚未成为同一条生产路径。

另外，02 的 `AgentMigrationStartup.CreateDefault` 明确安装不可用 runner：`bb3d167:src/windows/ReminNote.Agent/Runtime/AgentMigrationStartup.cs:47-51` 返回 `P275MigrationAssemblyUnavailable`，其 `RunAsync` 在 `bb3d167:.../AgentMigrationStartup.cs:83-96` 始终返回 `RECOVERY_REQUIRED`。这实现了安全失败，却不能证明正常迁移或启动可用。

02 的 `AgentMigrationStartup.DefaultPlan` 在 `bb3d167:src/windows/ReminNote.Agent/Runtime/AgentMigrationStartup.cs:14-26` 中把 source 和 target migration ID 设为同一组现有 migration；这不必然违反 forward-only 规则，但意味着默认 plan 没有真实 schema 变化的成功路径，不能替代 P2.75-04 对历史 upgrade clone 的 forward migration 证明。
